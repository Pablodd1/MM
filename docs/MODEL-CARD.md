# Model card — MM decision adapter v0.1

## What it is

A QLoRA adapter on **Qwen2.5-3B-Instruct** (Apache-2.0) that turns a computed decision situation
into a structured stance and reasoning. Base weights are unchanged; the adapter is 119.8 MB.

It is **not** trained on Mark Gomes's decisions. It is trained to reproduce the policy the app's
own engine applies, so the prose and the numbers agree.

## Training data

400 synthetic situations generated by `scripts/build_sft_dataset.py`, balanced 100 per stance
(add / hold / trail / pass). Each label comes from the shipped code — `rubric.score`, `rules.size_position`,
`decision._mm_action` — so the target is the engine's answer, not an opinion about it.

Reasoning text was written by grok-4.7 under a no-digits constraint; any completion containing a
numeral was rejected at build time. 400/400 cases passed.

Split: 340 train / 60 held out, stratified per stance, with an assert that no held-out prompt
appears in training. The first evaluation run (0.92) was discarded because it was leaky.

## Results (held out, n = 60)

| Metric | Value |
|---|---|
| Stance agreement with engine | **0.983** (59/60) |
| Per-class recall | add 0.93 · hold 1.0 · trail 1.0 · pass 1.0 |
| Digit-free prose | **0.983** (59/60) |
| Final train loss | 0.351 |
| Training | 212 steps, 5 epochs, ~10 min, RTX 5070 Ti 16 GB |

Confusion: one `add → hold`. The errors cluster on the add boundary, which is the engine's only
conjunctive rule (`score ≥ 8` **and** reward/risk ≥ 2).

## What it does not do

- **No investment skill is claimed.** Agreement measures fidelity to a deterministic rule table,
  not whether a call makes money. Accuracy needs closed journal horizons, which do not exist yet.
- **Not validated on real situations.** All cases are synthetic draws from the same generator, so
  distribution shift is untested. Real tickers with gaps, halts and earnings surprises are out of
  sample by construction.
- **No knowledge added.** Facts still come from the retrieval corpus and the market data layer.
- **One seed, one base model, 60 eval cases.** Differences smaller than a few points are noise.

## Serving

`scripts/serve_adapter.py` exposes an OpenAI-compatible `/v1/chat/completions` on localhost. Set
`MMDESK_LLM_BASE` / `MMDESK_LLM_MODEL` and the MM Opinion button uses the adapter with no code
change. Verified end to end: `/api/opinion` returned `mm-decision-3b @ 127.0.0.1:8899`, stance
`hold`, digits in prose `false`.

A 3B cannot run on Vercel. Live hosting needs a GPU endpoint (HF Inference Endpoint, RunPod,
Together/Fireworks LoRA hosting). The same OpenAI-shaped interface means that is a configuration
change, not a rewrite.

## Reproduce

```bash
.venv/Scripts/python.exe scripts/build_sft_dataset.py --n 400 --batch 10
trainenv/Scripts/python.exe scripts/train_decision_lora.py --epochs 5 --lr 2e-4 --rank 32 \
    --base Qwen/Qwen2.5-3B-Instruct
trainenv/Scripts/python.exe scripts/serve_adapter.py --port 8899
```
